技术修订与补充

以下内容已在相关段落直接调整或以“工程补充”说明。核对时间为 2026 年 10 月 25 日；具体 API 和配置须以实际使用的软件版本为准。

  • 第一章：区分 Web 请求量与数据库查询量的 QPS 语境；水平扩展不保证吞吐随实例数线性增长。
  • 第二章：说明浏览器、CDN、Redis 和数据库与 CPU 缓存层级只是类比；布隆过滤器的否定结论只适用于已正确加入集合的数据；重建缓存的伪代码加入获锁后重查、有限重试、TTL、唯一 token 和安全释放，说明租约过期的局限。
  • 第三章：区分 binlog 的语句与行格式；重新绘制读写路由，避免把全部读请求画成先经过主库；说明半同步复制确认 relay log 接收刷盘，不代表事务已在副本应用，也不消除读延迟或自动完成故障切换。
  • 第四章：随机 UUID 与有序 UUID 的索引局部性不同，不把所有 UUID 一概视为随机主键。
  • 第五章：区分发布确认、消费确认和业务完成；说明 RabbitMQ 确认与 Kafka offset 提交的差别；去重记录与业务变更需要同一事务及唯一约束；Redis 预扣库存与发 MQ 之间仍存在失败窗口，前台受理不等于成单。
  • 第七章：补充 DNS 缓存与健康检查对切换时延的影响，以及多地域容灾的容量、RPO 和 RTO 验证要求。
  • 第八章：修正“强一致使性能、可用性都非常高”的笔误；多数派交集需要结合协议规则；Raft 的当前任期提交、状态机应用、旧 Leader 和线性一致读均有额外条件；栅栏令牌必须由资源端原子执行校验与写入。

故事中的 CPU、QPS、延迟与数据量用于解释场景和计算方法，不是经过压测的产品性能指标。示例代码用于解释设计，具体实现需要结合事务、失败处理和实际客户端接口。
